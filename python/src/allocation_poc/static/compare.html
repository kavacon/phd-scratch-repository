What is and is not equivalent
  • Ours: inline the functions, insert the releases, pack registers into fixed slots with one shared scratch register, and write the gates (a Cuccaro adder, shift-and-add multiply, multi-controlled X comparisons).
  • Qrisp: the same task written by hand as ordinary Qrisp, using only what Qrisp provides: QuantumFloat registers, its own +, -, * and comparison operators, with condition: for an if, and @auto_uncompute for the temporaries. Nothing is wrapped or annotated, so the circuit is what Qrisp's compiler makes of the code, with its own adders, qubit allocation and ancillae.
  • So the gate constructions are not the same. This compares the two generation processes as they come, not matched adders.
  • Where the Qrisp text had to adapt to Qrisp: a QuantumFloat is a mantissa times a power of two, so multiplying by 2 only shifts the exponent and Qrisp then refuses to add an odd constant, so doubling is written a + a where that happens. Where our source updates a name inside an if, the Qrisp updates in place, but copies first where updating would stop Qrisp uncomputing the condition (one-armed). The measured value is the mantissa times two to the exponent.
  • What Qrisp leaves undone: @auto_uncompute does not clean a register loaded with a constant, so it is still set when the circuit ends. Run a circuit to see the qubits left set. In our compiler a constant is just a variable and is released like any other.
  • Same measuring: every circuit is read into Qiskit and counted the same way, as built (a multi-controlled X, or a Qrisp QFT, counts as one gate) and after Qiskit's optimiser into u and cx.
